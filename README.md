# hamap

hamap turns an ADIF ham radio log into a very high-resolution world map of your contacts, as a zoomable PNG or an interactive HTML page. Once the Natural Earth map data has been downloaded (see [Setup](#setup)), everything runs offline.

## Features

- Reads standard ADIF files from WSJT-X, Log4OM, HRD, QRZ Logbook and other loggers
- Places each QSO using the log's LAT/LON fields, its Maidenhead grid square, or, as a last resort, the center of its country
- Draws a great-circle line from your station to each contact, correctly split where it crosses the date line
- **Info boxes** list the callsigns worked, grouped by grid square, 4-character grid square, state/province or country, and are placed automatically around the map (optionally out over open water)
- **Shading** highlights every state, country or grid square you have worked
- **Color shows what belongs together:** a region's shading, dots, lines and info boxes share one color, and neighboring regions always get different colors
- **Profiles** (`small`, `big`, `grids`, `dxcc`, or your own) bundle settings; by default hamap picks one based on the size of your log
- **Automatic map area:** the map is cropped to your contacts plus a margin; `--extent full` shows the whole world (including Antarctica), `--extent poles` the world without the polar regions
- **Image mode:** a PNG 48 inches wide at 300 DPI (about 14,400 pixels, with the height set by the map area), detailed enough to read individual callsigns when zoomed in
- **HTML mode:** a single self-contained web page where you can change the shading, dots, layers, bands and date range live, pin draggable popups, and share a view by URL
- `--preview` opens the image in a window instead of saving it (image mode only)

## Install

Install hamap as a command-line tool with [pipx](https://pipx.pypa.io/):

```bash
pipx install .            # from a checkout of this repository
pipx install --force .    # upgrade after pulling changes
```

For development, an editable install picks up changes to the source immediately:

```bash
pipx install -e .
# or, in a local virtual environment:
python3 -m venv .venv && .venv/bin/pip install -e .
```

## Setup

Download the Natural Earth map data once (requires an internet connection):

```bash
hamap --setup
```

The data is stored in `~/.hamap/cartopy/`, and every run after that works offline.

## Usage

```
hamap [FILE] [OPTIONS]

Positional:
  FILE                  ADIF log file to map

Output (choose one; the default is image):
  --image               Generate a PNG image (default)
  --html                Generate a self-contained interactive HTML map

Profiles (see "Profiles" below):
  --profile NAME        auto (default), small, big, grids, dxcc, or one from your config file
  --config FILE         Profile config file (default: ~/.hamap/config.ini)
  --show-config         Print the settings that would be used and where each came from, then exit

General:
  --output FILE, -o     Output file (default: <input>.png or <input>.html)
  --preview             Open the image in a window instead of saving it (image mode only)
  --my-grid GRID        Your station's grid square (e.g. EN82), if the log doesn't include it
  --setup               Download the offline map data to ~/.hamap/ and exit

Map content (see "Map Content" below):
  --boxes UNIT          What one info box covers: grid (default), grid4, region,
                        country, or none (dots only)
  --box-calls N         Callsigns per box: all (default); N = the N busiest plus
                        a "+k more" line; 0 = a summary (calls, grids, QSOs per band)
  --band-colors on|off  Color callsigns by band (default: on); the band rows and
                        band key are shown either way
  --fill UNIT           Shade every worked area of this kind: none (default), grid,
                        grid4, region, country
  --names WHICH         Place-name labels: none (default), countries, states, all
  --borders WHICH       countries (default), or states to add US state and
                        Canadian province borders
  --grid-lines LEVEL    Maidenhead grid overlay: none (default), fields (20°×10°
                        lines with labels), squares (also 2°×1° lines)
  --ocean-boxes         Move info boxes out over open water when that isn't a long
                        detour, leaving room on land for inland boxes [--no-ocean-boxes]

Great-circle lines:
  --no-lines / --lines  Hide / show great-circle lines
  --line-alpha A        Opacity from 0 to 1, or auto (default: 0.45 for small logs,
                        fading toward 0.12 as the number of contacts grows)
  --line-width PT       Width in points, or auto (default: 0.8 for small logs,
                        thinning toward 0.4 as the number of contacts grows)

Canvas (image mode):
  --dpi N               Output resolution (default: 300)
  --width N             Image width in inches (default: 48); the height is set by the map area
  --extent MODE         auto  = fit your contacts and station, plus a margin (default)
                        full  = the whole world, including the poles
                        poles = the whole world without the polar regions (60°S–84°N)
  --font-size PT        Info box font size in points (default: 3.0)

Filters (applied before the map is drawn):
  --confirmed lotw      Only QSOs confirmed through LoTW (LOTW_QSL_RCVD=Y)
  --start DATE          Only QSOs on or after DATE (YYYY-MM-DD or YYYYMMDD)
  --end DATE            Only QSOs on or before DATE
  --tail-days N         Only QSOs from the last N days      [cannot combine with --tail]
  --tail N              Only the last N QSOs in the file     [cannot combine with --tail-days]

Logging:
  --verbose / --debug / --trace
  --logfile FILE        Also write the log to FILE
  --syslog              Also send the log to syslog
```

### Examples

```bash
# Save a PNG next to the ADIF file (the auto profile picks small or big)
hamap wsjtx_log.adi

# Use a specific profile, overriding one of its settings
hamap wsjtx_log.adi --profile big --box-calls 20

# Show which settings would be used, and why
hamap wsjtx_log.adi --show-config

# Grid chaser's map: every worked 4-character grid square shaded, with the grid overlay
hamap wsjtx_log.adi --profile grids

# LoTW-confirmed DXCC entities, one box and one shaded area per entity
hamap wsjtx_log.adi --profile dxcc

# One box per state or country, with worked grid squares shaded in each state's color
hamap wsjtx_log.adi --boxes region --fill grid4

# Interactive HTML map; change the view live in the page
hamap wsjtx_log.adi --html
hamap wsjtx_log.adi --html --profile grids   # opens on the grid square view

# QSOs from a date range, the last 30 days, or the last 500 QSOs
hamap wsjtx_log.adi --start 2025-01-01 --end 2025-03-31
hamap wsjtx_log.adi --tail-days 30
hamap wsjtx_log.adi --tail 500

# Choose the output file
hamap wsjtx_log.adi --output ~/Desktop/contacts.png

# Set your station's grid square (needed for great-circle lines if the log lacks it)
hamap wsjtx_log.adi --my-grid EN82

# Whole world, larger and higher resolution
hamap wsjtx_log.adi --extent full --width 64 --dpi 400

# Dots and shading only: no boxes, no lines
hamap wsjtx_log.adi --boxes none --no-lines
```

## Profiles

A profile is a named set of default settings. Settings are applied in layers, each overriding the one before:

**built-in defaults → profile (and any profile it extends) → command line**

For example, `hamap log.adi --profile big --box-calls 20` uses everything from `big` except the number of callsigns per box. Every on/off option has an "off" form (`--no-ocean-boxes`, `--lines`, and so on), so the command line can always undo a profile setting.

| Profile | Settings |
|---------|----------|
| `auto` *(default)* | Uses `small` or `big` depending on the log: `big` when it has 300 or more distinct 4-character grid squares (counted after filters). |
| `small` | `--boxes grid --fill region --names all --borders states` |
| `big` | `--boxes region --box-calls 12 --fill region --names all --borders states --ocean-boxes --line-alpha 0.40 --line-width 0.4 --width 64` |
| `grids` | `--boxes grid4 --fill grid4 --grid-lines squares --names countries`: a grid chaser's map |
| `dxcc` | `--confirmed lotw --boxes country --box-calls 12 --fill country --names countries --ocean-boxes --no-lines`: LoTW-confirmed DXCC entities |

Run `hamap log.adi --show-config` to see the settings that would be used, which profile `auto` chose, and where each value came from (`*` marks values that differ from the built-in default).

### Custom profiles

Define your own profiles in `~/.hamap/config.ini` (or a file given with `--config`). Keys are the long option names without the leading dashes, and on/off options take `yes` or `no`:

```ini
[defaults]
profile = poster            # used when --profile isn't given (instead of auto)

[profile:poster]
extends    = big            # start from big, then change:
width      = 80
extent     = full
line-alpha = 0.1

[profile:quick]
dpi        = 150
no-lines   = yes
```

A profile in your config file with the same name as a built-in one (`small`, `big`, and so on) replaces it, and `auto` uses your version. The input and output file, `--preview` and `--setup` can't be set in a profile.

## Map Content

Three independent choices decide what is drawn:

| Question | Option | Values |
|---|---|---|
| What does one info box cover? | `--boxes` | `grid`, `grid4`, `region`, `country`, `none` |
| What gets shaded? | `--fill` | `none`, `grid`, `grid4`, `region`, `country` |
| Which reference layers are shown? | `--names`, `--borders`, `--grid-lines` | see [Usage](#usage) |

**Units.** `grid` is the grid square as logged (usually 6 characters) and `grid4` its 4-character square. `region` is a US state or Canadian province, and a whole country everywhere else. `country` is the ADIF COUNTRY entity, so Alaska and Hawaii count separately from the rest of the US. A QSO's state comes from the log's `STATE` field when present; otherwise hamap looks up its position in the Natural Earth state and province outlines, using the nearest state or province for positions just offshore or on a lake. A QSO whose only known location is its country's center never counts toward a state.

**Color shows what belongs together.** Everything takes the color of the *larger* of the box unit and the shading unit. With `--boxes grid --fill region`, every grid box in Ohio shares Ohio's color and shading. With `--boxes region --fill grid4`, each state's worked grid squares are shaded in that state's color. With `--boxes grid4 --fill grid4`, each grid square gets its own color, matching its box. Neighbors always get different colors. Two areas count as neighbors if their outlines are close (states within about 1.5°, grid squares that touch) or if their boxes or dots end up close together on the map. The 8 colors were checked for contrast against both the ocean and the land, and colors that look alike, including to people with red-green color blindness, are kept apart where possible. `--verbose` reports how many neighboring pairs still ended up with similar colors.

**Bands appear inside the info boxes, not on the map.** Each box lists its callsigns in rows by band, lowest band first (`?` for QSOs with no band recorded). The band name starts the row, and the callsigns are printed in that band's color; a station worked on two bands appears in both rows. With `--box-calls 0`, each row shows that band's QSO count instead. Band colors are adjusted where needed so text has at least 4.5:1 contrast against the box background (160 m, 12 m and 10 m are slightly lightened). The **QSOs by band** key shows the total for each band and doubles as the color legend.

**Region and country boxes** get a single dot at the center of the area you actually worked (so "Russia" sits in European Russia if that's where your contacts were) and a single great-circle line. Grid boxes get one dot per grid square.

## Large Logs

hamap handles logs with thousands of QSOs, but how well the info boxes fit ultimately depends on how much room the map has. The `big` profile, chosen automatically for large logs, bundles the settings that work best. The individual options are:

- **`--boxes region`** groups boxes by state, province or country (for example, 568 grid boxes become 184 region boxes). **`--boxes grid4`** groups by 4-character grid square, usually about 40% fewer boxes than full grid squares.
- **A wider image** helps more than anything else. Text stays the same size in pixels, so a wider image gives each box more room. On a 1,600-QSO log with region boxes, leader lines were about 30% shorter (relative to the map) at 64 inches than at 48 inches, and about 47% shorter at 80 inches. The cost grows with the square of the width: about 95 megapixels and 1.2 GB of memory at 48 inches, 167 MP and 1.8 GB at 64 inches, and 261 MP and 2.7 GB at 80 inches. Some viewers, such as phones and web galleries, shrink or refuse images much larger than about 200 megapixels. `big` uses 64 inches.
- **`--box-calls N`** limits box size: `--box-calls 12` lists the 12 busiest callsigns plus a "+k more" line, and `--box-calls 0` replaces the list with a summary (callsigns, grid squares, QSOs per band).
- **`--ocean-boxes`** moves crowded coastal boxes out over the water so inland areas keep room near their dots. A box only moves to the water if the whole box clears land and the spot is no more than 2.5 times as far away as the nearest free spot on land, so boxes with room beside their dot stay put. It works best with region boxes; with grid boxes it tends to line the coasts with boxes.
- **`--line-alpha` and `--line-width`** (or `--no-lines`) adjust how strongly the great-circle lines show.
- **`--verbose`** prints placement statistics (leader line crossings, and median, 90th-percentile and longest leader lines) so you can compare settings.

**How boxes are placed.** Boxes in the most crowded areas are placed first. Each box searches outward from its dot in widening rings, trying positions right next to the dot in every direction, and picks the free spot that is closest while crossing the fewest existing leader lines. A final pass swaps any two boxes whose leader lines still cross, when both still fit; this always makes the pair's lines shorter. On a 1,600-QSO log with grid boxes, this reduced leader line crossings from about 7,900 to about 600, so leader lines fan out in parallel instead of crisscrossing, and total leader line length went slightly down.

## Interactive HTML Map

`--html` writes a single self-contained HTML file; it needs no internet connection or other files to open. The file contains everything needed for every view (grid square, 4-character grid square, state/province and country dots, shading outlines and colors), so you can switch between them instantly in the page. A 1,600-QSO log produces a file of about 9 MB.

### Map options panel

A panel in the top-left corner controls the map. Click **Map options** to collapse it; the page remembers your choice.

- **Fill:** shade by state/country, country, 4-character grid square, grid square, or nothing
- **Dots & popups:** what each dot and its popup cover, with the same choices
- **Layers:** great-circle lines, dot labels (for state and country dots), country names, state names, state borders, and the Maidenhead grid fields and squares
- **Dates:** a chart of your activity (QSOs per day, week or month, depending on how long the log covers) with a two-handle slider that moves a day at a time. Only QSOs in the selected range are shown; **all dates** resets it. The page always opens showing every date, and QSOs without a date only appear while every date is selected. (`--start` and `--end` still remove QSOs from the file itself before the map is made.)
- **QSOs by band:** the QSO count for each band in the selected dates. Untick a band to hide its QSOs everywhere: dots, shading, lines, popups and the activity chart. **all** and **none** tick or untick every band.

The band and date filters apply to everything at once, and the **statistics** box in the bottom-left corner updates to match what is shown.

Colors follow the same rule as image mode (see [Map Content](#map-content)): the larger of the dot and shading units decides, and neighbors always differ. With just `--html`, the page opens with **Fill: state/country** and **Dots: grid**. If you choose `--fill`, `--boxes`, `--names`, `--borders`, `--grid-lines` or `--no-lines`, or name a profile with `--profile` (or in your config file), those set the starting view instead. Options that only apply to images (`--width`, `--dpi`, `--font-size`, `--ocean-boxes`, `--box-calls`) are ignored. The page opens on the whole world (or without the polar regions with `--extent poles`); zoom in from there.

### Navigation and popups

- **Scroll or pinch** to zoom and **drag** to pan. The reset button in the toolbar (top right) restores the original view and closes all popups.
- **Hover** over a dot to see its name and how many QSOs and callsigns it has.
- **Click** a dot to **pin a popup** listing its QSOs in rows by band (lowest band first), each with callsign, name, date and location. QSO times are deliberately left out, since the file is meant to be shared. Popups update as you change the band and date filters, scroll when long, and stay attached to their dot as you pan and zoom (a thin line and a ring mark the dot). Drag a popup by its title bar to move it; close it with **×** or by clicking the dot again. You can have several open at once, which is handy for screenshots.

### Sharing a view

The page records its current view in the URL, so you can bookmark or share it. For example:

```
contacts.html#fill=region&dots=region&view=38,-92,3.2&bands=20m,40m&from=2025-06-01&to=2025-08-31&pin=Ohio,Texas
```

The URL can include `fill` and `dots` (`grid`, `grid4`, `region` for state/country, `country`, or `none`), `bands` (comma-separated list of the bands shown), `from` and `to` (dates as `YYYY-MM-DD`), `view=LAT,LON,ZOOM` (updated as you pan and zoom), `pin` (names of dots whose popups should open), `panel=0` (start with the panel collapsed), and `lines`, `labels`, `cnames`, `snames`, `borders`, `gfields` and `gsquares` (`1` for on, `0` for off).

## How Contacts Are Located

hamap places each QSO using the first of these it finds:

1. **LAT and LON** fields in the log, in ADIF's `XDDD MM.MMM` format (for example `N043 31.031`) or as decimal degrees. All-zero placeholder values are ignored.
2. **GRIDSQUARE**, a 4- or 6-character Maidenhead locator.
3. **COUNTRY**, matched against a built-in list of about 240 country centers.

QSOs with none of these are skipped (listed with `--debug`). QRZ Logbook and most modern loggers include a position or grid square on nearly every record, so in practice few or none are skipped.

## Map Style

- Dark navy ocean and dark sand-colored land, with Natural Earth coastlines and borders at 1:10 million scale
- Dots, lines, info boxes and shading colored to show what belongs together (see [Map Content](#map-content)); dots have a dark outline so they stand out against the lines
- Your station is marked with a yellow star
- Info boxes have their header and border in the area's color and list callsigns in rows by band, in a monospace font sized for zooming in; long rows wrap into columns
- Great-circle lines become fainter and thinner as the number of contacts grows
- Place names that would overlap one already drawn are skipped (states first, then countries from largest to smallest); very small countries are not labeled
- The statistics box (station call, contacts, grid squares, callsigns, countries, US states, Canadian provinces, first and last QSO date, and any filters used) and the **QSOs by band** key scale with the image and go in the corners with the fewest contacts
